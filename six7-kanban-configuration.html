1. Before you start#

1.1 What Kanban does for you#

Six7 Kanban gives you boards with columns and cards, so work moves from To do to Done where everyone can see it. Each board can also be run as a small project, with a goal, a target date, a status and milestones. The home screen shows every project at a glance.

People open it from one link. The main screens are Boards, My cards, Calendar and Reports, plus Admin tools for Admins. The Kanban User manual shows each screen.

1.2 What Six7 has installed#

Everything is in the owner account (§1.3):

PartWhat it is
The SheetA Google Sheet named like Six7 Kanban — your company. It holds the boards, cards, comments, settings and users
The scriptKanban's ten files, attached to the Sheet (Extensions › Apps Script)
The web appThe link people open. The Sheet's Six7 › Open app opens it too
The Files folderSix7 Kanban — Files in the owner's Drive, with a Reports folder inside for report files
Four timed jobsThe nightly job (00:00–01:00), a cleanup (02:00–03:00), a daily job (05:00–06:00) and the digest (07:00 by default). Times are in the Sheet's time zone

The general model is in Suite §3.

1.3 Your owner account Solo#

Kanban is installed in your own @gmail.com account. On a personal account Kanban is for you alone, as its Admin: Google can't tell the app who other people are outside a Workspace domain, so only you can open it. Moving to Google Workspace later makes it a team app (Suite §4).

Expect a few things that differ from a Workspace install:

  • Google shows "This app isn't verified" the first time you run Setup / repair (§2.1).
  • The setup summary shows ✗ for the browser tab icon. That's expected: a personal account can't share the icon with a company, so the tab shows Google's icon.
  • A personal account can send fewer emails a day (§6.3).

1.3 Your owner account Team#

Kanban runs as a dedicated owner account in your Workspace (Suite §5).

If your company also uses another Six7 app, Kanban gets an owner account of its own, for example six7-kanban@yourcompany.com. A live board checks for changes every few seconds while people use it, and Google's limits belong to the owner account, so Kanban doesn't share them with the other apps. If Kanban is your only Six7 app, it can use a shared account such as six7-admin@yourcompany.com.

The owner account needs a Google Workspace licence and 2-Step Verification, and is used only for Six7.

1.4 What the Workspace admin may need to do Team#

Your Google Workspace admin may be asked to:

  • let Six7 deliver the app: in the Admin console, API controls may need to trust clasp, the Google tool Six7 uses during a delivery window (Suite §8);
  • make the app easy to find, once it's live: a short address or an intranet link, a tile in the Google apps menu, or a managed browser bookmark. Six7 provides the app's icons.

2. First sign-in and setup#

2.1 Run Setup / repair#

Six7 installs the app. Then the owner account finishes it:

  1. Open the Sheet as the owner account.
  2. Click Six7 › Setup / repair.
  3. Google asks the owner account to allow the app. Tick Select all, then click Continue. A run with a permission left unticked stops and asks again.

Solo

Before that, Google shows "This app isn't verified", because the app is your own private copy and isn't published by Google. Click Advanced, then Go to … (it says unsafe), then Select all and Continue.

Setup / repair creates the tabs, the Files folder and the four timed jobs, and adds the owner account as the first Admin. It's safe to run again: it only adds what's missing, and a second run starts with ✓ Already up to date.

2.2 Read the setup summary#

Setup / repair ends with a summary in a dialog:

  • one line per change, marked ✓, or ✗ for a step that couldn't run;
  • then the Check installation lines (§2.3);
  • and "Setup complete (version 0.1.0)." last.

If a line shows ✗, run Setup / repair once more. If it still shows ✗, send Six7 a screenshot (Suite §10).

Solo The ✗ for the tab icon is expected on a personal account (§1.3).

2.3 Check installation#

Six7 › Check installation in the Sheet, or Admin tools › Check installation in the app, checks the install at any time. Each line is ✓ (fine) or ✗ (to fix):

LineWhat it checks
Files and versionsKanban's code files, all at the same version
PermissionsThe permissions the app needs
Advanced Drive serviceTurned on, so file sharing sends no extra emails
EmailHow many email recipients the owner account has left today
Time zonesThe script's and the Sheet's time zones agree
TriggersThe four timed jobs, owned by the owner account
FoldersThe Files and Reports folders, and the tab icon
OwnerThe account recorded as the owner
app.urlThe app's address, recorded on its first visit (§2.4)
Tabs and columnsEvery tab and column the app needs
Live boardHow many boards have their recent changes in Google's cache

Run it after every update and whenever something seems wrong.

2.4 Open the app for the first time#

  1. As the owner account, click Six7 › Open app in the Sheet. Before the first visit, it says how to find the address in the script editor (Deploy › Manage deployments).
  2. The first visit records the app's address (app.url). Emails and copied links use it from then on.
  3. Bookmark the link. Sign in as described in Suite §5.

As an Admin you see Admin tools beside Boards, My cards, Calendar and Reports.

Interaction gate, also on that screen, is a test tool Six7 uses to measure the app's speed on a release. You don't need it.

3. Company settings#

Settings live in the Sheet's _Settings tab: one row per setting, with Key, Value and Description. Change only the Value cell. The app picks a change up within a minute. After changing digest.hour, run Six7 › Setup / repair so the digest moves to the new hour.

3.3 Lists and rules#

The _Lists tab needs no change. Most of its lists are fixed by the app: board visibility, project status, column kinds, roles, notification choices and report email choices. LabelColour holds the seven label colours.

Boards, columns, labels and milestones are set up in the app, not in the Sheet, by each board's Board admin (User manual, §3). When a board is created, its Board admin picks the columns to start with:

TemplateColumns
BasicTo do, Doing, Done
Team workflowBacklog, To do, In progress, Review, Done
ProjectTriage, To do, Doing, Done, Not now

WIP limits. A column can have a limit on the cards in it: type a number in the WIPLimit column of the Columns tab. The board's admins then see columns over their limit in their daily digest. The limit never blocks a move.

4. Users and roles#

4.1 You are the Admin Solo#

On a personal account you are Kanban's only user and its Admin, and you're the Board admin of every board you create. There's nobody to add and nothing to assign. Skip to §5.

When your company takes on people, Kanban moves to Google Workspace and this chapter applies (Suite §4).

4.2 Roles in Kanban Team#

Kanban has two kinds of role. App roles are set in the _Users tab:

App roleTypical personSeesCan
MemberAnyone in the companyBoards they belong to, and Open boardsCreate boards (and become their Board admin); work on boards as their board role allows; run reports on the boards they see
ManagerA lead across several teamsEvery board, private ones includedReports across boards and the report email; restore archived boards; act as Board admin on any board
AdminWhoever runs the appEverythingAll of the above, plus settings, users and Admin tools

Board roles are set by each board's Board admin, in the board's Settings:

Board roleCan
Board adminEverything on the board: its name, project, columns, labels, milestones, members and visibility; archive it. A board always keeps at least one
EditorCreate, edit, move and archive cards; tick checklists; comment
ViewerRead and comment

Board members must have an address in your company's domain. There are no outside guests.

4.3 Add, change and remove people Team#

Most people need no setup. Someone in your company who opens the app is added to _Users as a Member on their first visit, with the daily digest on (with access.unlisted = Member, the default).

Add a row in _Users only for people who need something else:

ColumnWhat to type
EmailTheir work address
NameTheir name as people know it
RoleMember, Manager or Admin
ActiveTicked
DigestTicked for the daily digest
NotifyImmediately (an email at once when assigned or mentioned) or Digest only
ReportEmailOff, Daily or Weekly. Leave it blank: Setup / repair makes it Weekly for a Manager and Off for anyone else

People can change their own Notify and Digest later in the app, under Your settings.

When someone leaves:

  1. In Admin tools, use Replace a member: choose the person and who takes over, then See what changes. The replacement takes their place on every board, with the same board role, and gets their open cards. Finished and archived cards keep the original name, for reports.
  2. In _Users, untick their Active box. Don't delete the row. An inactive person can't open Kanban.

4.4 People you didn't add Team#

The access.unlisted setting decides what happens when someone in your company opens Kanban without a row in _Users:

  • Member (the default): they're let in as a Member and added to _Users. They see the Open boards and any board they're added to.
  • None: they see "You don't have access to Six7 Kanban yet. Ask one of these admins to add you", with the Admins' names. Use it when only a listed group should use Kanban.

People outside your company's domain never get in.

4.5 Scope and visibility Team#

Each board is Private or Open:

  • Private (the default): only its members see it.
  • Open: everyone in the company can view it and comment; only its members edit.

Managers and Admins see every board, private ones included, and the board settings say so. Everything follows these rules: the boards, search, the calendar, reports, exports and emails.

Example: Diego creates the private board Q4 customer onboarding and adds Sofía as an Editor. Sofía and Diego see it; Tomás, a Member, doesn't; Carolina, a Manager, sees it and its project status on her home screen.

4.6 Backup Admin and Sheet editors Team#

  • Give a second person the Admin role, so someone can always run Admin tools.
  • Only the owner account and that backup Admin should be able to edit the Sheet. Everyone else uses the app. See Suite §7.

5. Your data#

5.1 Start empty, with demo data, or with your own#

  • Empty. The usual start: Board admins create boards in the app.
  • Your own tasks, from a spreadsheet: §5.2.
  • Demo data: a year of a fictional company's boards, for trying Kanban out. Six7 loads it only into a demo install, never into the one your company will use, because the app has no step to remove it.

5.2 Import from a spreadsheet#

  1. Create the boards first, in the app, with their members.
  2. In the Sheet, check File › Settings › Locale, so the dates you paste are read the right way.
  3. Paste rows into the Cards tab, below the header. Leave ID and the system columns blank, and fill in:
ColumnWhat to paste
BoardNameThe board's name, exactly as in the app
ColumnNameThe column's name. A column that doesn't exist is added at the end of the board. Without one, the card lands in the board's Triage column, or its first
TitleThe card's title
DescriptionLonger text, if any
AssigneesWork email addresses, separated by commas
DueDateThe due date
ChecklistItems separated by ;

Labels and milestones aren't imported: add them on the cards afterwards.

  1. In the app's Admin tools (or Six7 menu), run Validate data. It lists problems by row and changes nothing. Fix them.
  2. Run Import pasted rows. The cards keep the pasted order, assignees who aren't on the board are added as Editors, and nobody is emailed.

5.3 Export and backups#

  • Google keeps the Sheet's history. File › Version history shows earlier versions and can restore one.
  • A copy for safekeeping: File › Make a copy saves a snapshot of the data. Never ask people to use a copy: it has no app and no timed jobs.
  • Exports from the app: every board has Export to Sheets, and every report can be exported to Sheets, a Doc or a PDF.
  • Nothing is deleted. Archived boards, columns, cards and removed comments stay in the Sheet. Old finished cards move to the CardsArchive tab, and reports still read them.

6. Emails and notifications#

6.1 What the app sends and when#

EmailWho gets itWhen
Assigned to a card / mentionedThe person assigned or mentioned, never the person who did itAt once, or in their digest if they chose Digest only. At most one per card in 10 minutes
Daily digest "your day"Everyone with the digest onAt digest.hour, only when they have overdue cards, cards due, or notifications waiting. Board admins also get columns over their WIP limit and cards assigned to people who left the board
Boards overview (the report email)Managers and Admins (every board) and Board admins who ask for it (their boards), with ReportEmail = Daily or WeeklyRight after the digest; weekly emails go on Mondays, with each board's What moved

Imports never send email.

6.2 Turning them on or off#

  • Each person sets their own: Your settings (their name at the top right) › Notifications. They choose an email at once or the digest, and whether to get the digest at all.
  • The report email: an Admin sets ReportEmail in _Users.
  • Admin tools › Send report email now sends the boards overview at once, to every Manager and Board admin who asked for it, or to you only, to see what it looks like.

Solo You get your own digest, and your boards overview every Monday unless you set your ReportEmail to Off. Nobody else is emailed.

6.3 Daily quotas#

Every email counts against the owner account's daily limit, set by Google. Check installation shows what's left today.

Team

A Workspace account can send to about 1,500 recipients a day. At the design load of 50 people, Kanban sends about 200.

Solo

A personal account can send to about 100 recipients a day. Kanban sends you a few.

Emails over the limit are skipped, not sent later. Cards, comments and notifications stay in the app, and the next day's emails go out as usual.

9.2 Updates from Six7#

Six7 delivers updates through a delivery window, as in Suite §8. After an update:

  1. Run Six7 › Setup / repair as the owner account. It adds what the new version needs. If it asks for a new permission, allow it.
  2. Check that the app's footer shows the new version.
  3. Run Check installation.

People's open pages pick the new version up the next time they reload.

9.3 Going back to the previous version#

Ask Six7. It's done like an update: the app's address stays the same, and your data stays as it is, because Setup / repair only ever adds to the Sheet.

9.4 Security and privacy#

On top of Suite §7:

  • Private boards stay private in every screen, search, calendar, report, export and email.
  • Who changed what: the _Audit tab records every change except moves within a column, and each card shows its History.
  • Comments: the author can edit or remove a comment for 15 minutes, and a Board admin can remove any. A removed comment's text stays in the Sheet, for the record.
  • Files on cards are off in this release.

9.5 Stop, park or remove the app#

Kanban stops from the Danger zone, at the bottom of the Sheet's Six7 menu: Park, Resume, Retire (keep the Sheet) and Wipe. Only the owner account can use them; anyone else gets "Only the owner account can run Park."

In this version you can Park and Resume. Retire and Wipe come with the next version; until then they answer: "Retire comes with the next version of Six7 Kanban. To stop the app now, use Six7 › Danger zone › Park: it keeps everything, and Resume brings it back."

Park stops Kanban until you resume it, and keeps everything:

  • it deletes its four triggers: Nightly, Cleanup, Daily job and Digest;
  • its address answers one line to everyone: "Six7 Kanban is parked. Ask the owner, the owner account's address, to resume it.";
  • no email, digest or report goes out, and nothing runs in the background;
  • the Sheet, the Files folder with the boards' files, and every report stay as they are.
  1. As the owner account, open the Sheet and click Six7 › Danger zone › Park.
  2. Read what will happen, type the Sheet's name to confirm, and click OK. Capitals, spaces and the kind of dash don't count: a plain - works for the — in Six7 Kanban — your company. With any other name, nothing changes: "That isn't the Sheet's name, so nothing was changed."
  3. The summary ends with "Parked (version 0.1.0)." The owner account also gets it by email, "Six7 Kanban was parked", and _Audit records a PARK row. If a step failed, the last line adds "Fix the lines marked ✗, then run Check installation again."

While it's parked:

  • Whoever opens the address sees only the parked line, the owner account too, so Admin tools can't be reached. Team That includes every Admin and the Manager.
  • A board that was already open shows the same line when someone next moves a card, edits something or opens a card, and nothing is saved.
  • Setup / repair still repairs the install, so Six7 can deliver an update to a parked Kanban, but it installs no trigger: "⚠ Parked since … by …: no trigger was installed. Six7 › Danger zone › Resume brings it back."
  • Check installation starts with "⚠ State: Parked since …" and shows "✓ Triggers: none, as a parked install should have". If a trigger was left behind, it names it, and Park again removes it.
  • Validate data starts with "Parked since … by …".
  • In the Sheet's Six7 menu, Run reminders now and Send report email now don't run: "Run reminders now doesn't run: Six7 Kanban is parked. Six7 › Danger zone › Resume brings it back." The rest of the menu still works for the owner account: Open app, Setup / repair, Validate data, Import pasted rows and Check installation.

Resume brings Kanban back, at the same address:

  1. As the owner account: Six7 › Danger zone › Resume, and type the Sheet's name.
  2. It clears the app's cached copies of the Sheet, so the app works from the Sheet as it is now, and installs the four triggers again, with the digest at digest.hour. The address opens the app again for everyone with access, and emails, the digest and reports go out again from their next run.
  3. The summary ends with "Resumed (version 0.1.0)." The owner account gets "Six7 Kanban was resumed", with an Open Six7 Kanban button, and _Audit records a RESUME row.

Closing the address is optional, and only by hand. Park keeps the address, so anyone who opens it reads the parked line. To close it: open the Sheet › Extensions › Apps Script › Deploy › Manage deployments, choose the web app, and Archive it. Opening Kanban again then needs a new address: after Resume, make a new deployment, clear app.url in _Settings, and open the new address once as the owner account. Six7 can do it with you in a delivery window. Old bookmarks, pinned apps and links in past emails keep pointing at the closed address, Team and so does Kanban's tile in the Google apps menu if you added one (Suite §5).

I trashed the Sheet. Has Kanban stopped? No. Its address still opens the app, and its triggers are still installed. Restore the Sheet from Drive's trash, Park it and close its address, then trash it again if you want to. Or, without restoring it, delete its triggers as the owner account at https://script.google.com/home/triggers: ⋮ › Delete trigger on each one. That stops its jobs, but its address keeps opening the app until you restore the Sheet and close the address. The triggers page names each row by its project only, and two installs can share a name, so check ⋮ › Project details before you delete.
